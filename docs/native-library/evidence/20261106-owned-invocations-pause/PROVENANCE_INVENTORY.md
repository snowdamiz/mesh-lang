1. **Direct generated entry and ownership.** The compiler already generates an internal `__mesh_library_entry_<symbol>` thunk; the public export wraps it with `mesh_library_invoke_bounded` ([codegen/mod.rs:429](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-codegen/src/codegen/mod.rs:429), lines429–495). That legacy runtime path acquires `CALL_LOCK`, creates a temporary PID, clears the inherited yielder, and executes synchronously ([library.rs:441](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/library.rs:441), lines441–479). **Minimal change:** generate a separate trusted entry/descriptor path passing the direct thunk and declared limits into an owned scheduler task. Copy native input before enqueue; allocate managed input under its actual process; copy/root results before process teardown. Do not enqueue the public legacy wrapper.

2. **Scheduler context and execution lane.** `spawn_process` captures the current `Arc<InvocationContext>`; `resume_process` installs it beside the PID ([scheduler.rs:311](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/scheduler.rs:311), lines936–944). Coroutine creation establishes its own stack base/yielder ([stack.rs:180](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/stack.rs:180), lines180–200). Reuse these mechanisms. However, `mesh_rt_init_actor(1)` **does not guarantee one execution lane**: an existing scheduler wins, and environment/embedded configuration can select more workers ([actor/mod.rs:233](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/mod.rs:233), lines233–255). Explicitly route protected processes and descendants through one existing worker, or refuse unsupported scheduler configurations. Add original-context cancellation/liveness checks before first execution and resume; these checks do not replace sink admission.

3. **Actors, jobs, and root completion.** Ordinary/shaped spawn and linked jobs share the original invocation. Job creation and completion use `spawn_linked` and a control-mailbox result ([job.rs:94](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/job.rs:94), lines94–144). Spawn arguments copy managed buffers and retain heap loans; nonmanaged pointers remain caller-owned ([scheduler.rs:867](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/scheduler.rs:867), lines867–900). Therefore the new task payload must have explicit ownership even if cancelled **before its entry runs**; a raw `Box::into_raw` reclaimed only inside entry is insufficient. Root-result completion must be separate from descendant/worker settlement. Preserve original tombstones and Host references after root return; never substitute a fresh invocation. Explicit cancellation should mark the invocation and wake its owned processes without joining external workers.

4. **Ordinary messages and channels currently transfer data, not authority.** `Message` contains only `MessageBuffer` ([process.rs:227](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/process.rs:227)); local delivery queues it without checking sender/recipient invocation, and receive simply materializes it ([actor/mod.rs:625](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/mod.rs:625), lines625–664,803–835). Channels likewise retain payload/heap ownership without invocation provenance ([channel.rs:229](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/channel.rs:229), lines229–264,272–336). **Bounded implementation:** permit transfers only within the exact same `InvocationContext`, checking both sender and receiver; refuse scoped↔unscoped and different-invocation transfers before enqueue/dequeue. Use invocation identity, not merely the same `NativeAuthority`. Channels need an immutable owner or an explicit protected refusal. Heap loans are not authority.

5. **Services require a separate dispatch-lifetime design.** Calls enqueue `[tag, caller_pid, payload]`; casts and replies also lack provenance ([service.rs:68](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/service.rs:68), lines68–115,149–185). Generated service loops receive, invoke a handler, reply, update persistent state, and loop without an authority enter/leave boundary ([codegen/expr.rs:3797](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-codegen/src/codegen/expr.rs:3797), lines3797–3950). Adding metadata alone cannot fix this: scheduler resume would reinstall the service’s creation context. **R2 boundary:** refuse shared/cross-invocation calls and casts before installing monitors or queueing requests; preserve same-invocation service operation only if deliberately tested. Full support needs per-dispatch context surviving suspension, restoration on every handler exit, reply correlation, and persistent-state/resource ownership rules. Keep bit16 off.

6. **Timers have two materially different routes.** `Timer.apply_after` creates an ordinary actor, so original invocation and closure loans propagate; actual dispatch occurs after `mesh_timer_sleep` ([actor/mod.rs:986](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/mod.rs:986), lines986–1007). Preserve this and check cancellation before callback execution. `Timer.send_after`, however, creates an OS thread retaining only `SendOnTimer`; neither invocation nor cancellation is captured ([actor/mod.rs:1018](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/mod.rs:1018), lines1018–1057). Refuse it early in protected execution, or move it onto an owned timer process and enforce same-invocation delivery at firing. The shared timer reactor’s PID-only wake is scheduling, not authority transfer. Existing R1 timer proof exercises **apply_after**, not send_after.

7. **Supervisors and restarts are unqualified.** `ChildSpec` stores raw function/argument pointers without authority or retained argument ownership ([child_spec.rs:96](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/child_spec.rs:96)). Initial children inherit the starting caller’s context; restart calls inherit the supervisor’s then-current context through `spawn_linked` ([supervisor.rs:135](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/supervisor.rs:135), lines135–150,338–359). A same-origin supervisor can retain provenance today, but no per-child invariant enforces it. Shutdown also sleeps while callers hold supervisor state locks (lines212–223; `actor/mod.rs:1291,1390`). **Minimal boundary:** refuse protected supervisor start/management before state registration/spawn. Later support needs immutable per-child provenance, owned restart inputs, no restart after cancellation, and shutdown waits outside resource locks. `start_child` currently returns `u64::MAX`; it is not implemented dynamic propagation.

8. **Links, monitors, termination registration, and exit signals are additional escape routes.** Public link/monitor operations can create remote traffic; terminate registration can install a callback on another PID; exit signals can cause another process’s terminate/restart behavior ([actor/mod.rs:1111](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/mod.rs:1111), lines1111–1143,1440–1544). Apply the same invocation boundary to these APIs, including target ownership before mutation. Runtime job-result, DOWN, and exit delivery must remain distinguishable from application sends. Cleanup notifications do not grant authority to a recipient or restarted process.

9. **Remote sends/spawns cannot propagate the native authority as implemented.** `DIST_SEND` contains target/data/captured values, with no invocation identity ([dist/node.rs:1762](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/dist/node.rs:1762)); receive dispatch directly calls `deliver_remote` at2183–2185. `DIST_SPAWN` resolves a registered function and spawns from the reader thread at2301–2327. Outbound spawn may connect, queue, reconnect/retry, then wait at7905–8084. **Refuse protected remote send, delayed remote send, spawn, link, monitor, and global registration before serialization/connect/enqueue.** Reject unqualified remote ingress into protected processes. Serializing an invocation number cannot reproduce original native tombstones/Host ownership.

10. **Ordinary HTTP workers retain the right context, but cancellation cleanup needs extension.** `send_cooperatively` captures context before spawning, installs it inside the worker, and admits the fixed request there ([http/client.rs:843](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/http/client.rs:843), lines843–882). Redirects are disabled for scoped requests at754–756. Preserve that. The active registry entry is removed only on the normal return path at881; dropping a suspended coroutine skips it. Add an owned request guard that removes the entry and signals cancellation on every exit. The worker must retain authority/Host until actual completion; cancellation or timeout is not evidence that network work stopped. Keep protected streams refused before worker creation at1032–1035.

WebSocket connection workers and accept/reactor callbacks lose originating context ([ws/client.rs:375](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/ws/client.rs:375); [ws/server.rs:398](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/ws/server.rs:398), lines398–429). HTTP serving can inherit a listener invocation into handlers but has no qualified inbound-owner contract ([http/server.rs:1253](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/http/server.rs:1253), lines1253–1338). Distribution also creates routed HTTP tasks, declared work, automatic recovery, continuity workers and consensus tasks (`dist/node.rs:5545–5576,7489–7521`; `continuity.rs:2328`; `continuity_store.rs:1772`; `consensus.rs:241,577,709`). Refuse protected entry before bind/connect/registration/queueing; cover existing-handle operations too. Context-free worker execution must never silently become standalone permission.

12. **Normal-stack Host callbacks preserve context but remain synchronous.** Host selection uses `context.original.callbacks`, not the replaceable V1 global table ([library.rs:323](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/library.rs:323)). `on_native_stack` uses the same worker’s parent stack, temporarily clearing its yielder ([stack.rs:119](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/stack.rs:119), lines119–139). Preserve this borrowed-buffer lifetime. It does **not** make a blocked Host callback parkable: one blocked callback occupies the execution lane. Qualify asynchronous Host/SDK waits separately or refuse them. Add explicit nested-entry rejection for the new API and legacy-wrapper entry from a scheduled Host callback; scoped V2 already rejects nested context at `authority.rs:302`. Retain native context/global references, never foreign `JNIEnv`, PID, or yielder.

13. **Cancellation/finalization ordering is a critical implementation gate.** An exited suspended process is finalized before its coroutine handle is dropped ([scheduler.rs:923](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/actor/scheduler.rs:923), lines923–933,965–978; caller drops at701–708). Finalization takes the invocation, runs terminate, closes SQLite/secrets, and removes the process at1059–1145. Suspended Rust-frame destructors therefore run later, outside that installed context and after process removal. For R2, unwind/drop the owned continuation under a valid, explicit cleanup frame before destroying resources its frames may own; settle completion exactly once for prestart cancellation, parked cancellation, panic and normal return. Do not accidentally give terminate callbacks a fresh resource-opening grant merely by leaving a PID installed.

14. **SQLite and resource-lock suspension guards must be centralized.** Current `may_suspend` checks the invocation’s transaction count, and only HTTP calls it ([authority.rs:102](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/authority.rs:102)). Transaction tracking follows SQLite autocommit, so it conservatively covers all open transactions ([sqlite.rs:73](/Users/andreyyurlov/Documents/dev/mesh-lang/compiler/mesh-rt/src/db/sqlite.rs:73)). Required coverage includes reduction yields, receive/job/service waits, sleep, cooperative receive/timeout, channels, and external blocking fallbacks (`stack.rs:99`; `actor/mod.rs:150,178,355,803,930`; `channel.rs:272`). Guard **before** registering a wait or dispatching external work, with a final guard at `yield_current`. Track resource-mutex ownership with scoped guards, including the platform storage lock at `storage_wrapping.rs:1089,1117`. Refusal must unwind and roll back owned provisional transactions; never admit the entire callback. Keep protected SQLite creator cleanup at `sqlite.rs:120–140`: root exit currently closes root-created handles even if a descendant shares invocation. Supporting a descendant’s continued handle use requires explicit resource lifetime ownership; do not silently weaken cleanup.
