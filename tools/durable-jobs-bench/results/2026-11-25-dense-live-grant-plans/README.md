## Native booking

The [controller packet](controller-packet.json) requests one five-minute SETUP and one twelve-minute build-free TIMING after existing reservations. The sole controller owns the journal, remote access, authenticated host and lock checks, upload, both releases and cleanup. There are six measured arms, in two rotations of off A / sampled / off B and off B / sampled / off A. Stage once, run each arm once, and stop on the first incorrect or incomplete arm. Preserve evidence and release through the usual lock check. There is no automatic retry, extra polling, peer run or candidate booking.

The frozen grouped hot D2 lane uses the exact public ELF and broker, one durable producer transaction and a 1 KiB payload in each of 1,024 jobs. Both 32-slot runners and all 32 warm application TLS sessions come from the public inventory. The original three-second idle priming and stock completion observer are preserved. Each arm drains a fresh real table through concurrent public runners. The observer attaches to the three existing counter queries and takes a post-disconnect readback just before the harness reads the terminal rows. The final bracket is a flush-checked whole-workload scope and can include stock observation and shutdown-tail work. The trace uses an absolute private module path with 35% sampling, actual rows and loops, verbose predicates and query IDs, buffers, WAL and nested statements, with per-node timing off. Only `parity_subject` logins on `mesh` receive the trace settings. The two executable identities, each runner's TCP client-port match to a TLS backend and captured logging PIDs establish who ran the statements. Effective PostgreSQL roles may differ inside a function.

The replay joins the plan ID to the PostgreSQL statement key and checks coverage for the grant, expiration and due recovery, scalar settlement and grouped settlement. Inspect the jobs scans under the `picked` CTE and the grant's ModifyTable join separately. Compare their index paths with the before/after relation and index deltas and then check recovery and settlement. Statement totals nest and overlap, parent plan buffers include children, and row counts and removal counts are printed per loop with rounding. PG17 index-only heap fetches are different from the plan's actual rows, and bitmap heap work can appear at relation level without appearing in an individual index's `idx_tup_fetch`. Neither sample rates nor run-to-run changes justify projecting counts or elapsed costs beyond the measured arms. Report observer overhead against duplicate controls on both submit and drain clocks. A product change needs a repeated material live shape and a separate qualified comparison against River and Oban on both clocks.

Run `python3 -B controller.py replay` after the controller exports both groups and the TIMING release at `evidence/native/controller-release.json`.
