The public LARGE FILE timing used the public runner ELF and a separate, warmed producer broker. The broker reads the requested fixture inside the measured window, prepares bounded specification strings and calls the ordinary transactional Jobs enqueue path. Reading the file there saved 293 ms to producer commit at the paired median against the faster same-broker inline duplicate on EXTERNAL. File transport is an application integration choice. ## Proposed runtime change

Apply candidate.patch to the public runtime at b3557273d72be3802bf189b284e7caaf5f3caa0f. The preimage SHA-256 for compiler/mesh-rt/src/jobs/store.rs is d7bebfcf384e488ba25e8f40d294d55c1efdb4006a3613cb899ac6b08c8782ab. The patch uses the stock untagged decoder and the existing JobSpec validation, policies, limits, and SHA-256. It moves the validated args tree into the normalized object when an immediate string field is at least 64 KiB and accounts for at least half the input. The fast path requires every byte to pass the compact JSON string escape check. Keys and all other values go through serde_json in the existing map iteration order. An escape in a candidate string sends it through ordinary serialization; late escapes can therefore add scanning cost. [Source overlay](candidate.patch)

The earlier move-and-serialize component saved 34.542 CPU-ms per submission against the faster duplicate at the paired median. It needed 5.458 ms more to reach its 40 ms threshold. That earlier treatment moves both args and metadata and uses an ordinary byte serializer. This treatment moves args and copies the dominant plain string directly. Its incremental gain is unknown. Instrumented stock serialization took 48.911 ms across the submission and included all fields and output allocation. That time cannot be added to the earlier saving. ## Qualification and decision

Use the sole controller for Linux compilation and any product execution. Compare original public stock, the previous moving serializer transferred to the same source, and the new candidate against all retained frames. Verify exact admission bytes and error behavior on objects, positional specifications, ordinary and mixed batches, duplicates, multibyte keys and values, escape offsets including the last byte, U+0000 through U+001F, quotes, backslashes, the size boundary, normalizers and retries. Check valid and invalid UTF-8 at the existing input boundary as appropriate. Include branch coverage and a case where a second large escaped or nested value delegates to serde_json. Byte equality, all existing transactional and wire error controls, and matched physical work precede performance claims.

The prior native stage and 40 ms component gate give a scale for an initial screen. A useful product result requires fresh FILE-vs-FILE measurements through durable enqueue and settlement, with duplicate stock controls, the same producer and runner roles, PostgreSQL storage, input, CPU and durability. Preserve the earlier release and each peer comparison separately. Producer changes alone leave the existing Oban drain deficit open.
