# Public SLOW FILE producer and runner topology

The released cap-68 public SLOW campaign used the Linux `b3557273` fixture on CPUs 0 and 1. Mesh beat River from submit to final durable settlement in two of five groups. The losses in groups 1, 2 and 5 were 94.909, 183.206 and 96.569 ms. Mesh led Oban in all five groups by 128.666–259.639 ms. Apalis led Mesh in all five groups. The stock enqueue window was 509.916–557.384 ms and the drain was 1,313.707–1,436.296 ms. The new comparison has two separate mechanisms that could move these clocks. ## Frozen execution

The released matrix selected `product-bulk` on the repaired public adapter. Migration and the runner use ELF `af2aca867a02…`. The original broker also used that ELF. The harness writes the normalized `batch_000000.json`, hashes it, waits for broker and runner readiness, and idles for three seconds. The producer wrapper stamps submit before inline Python reads and decodes the file, encodes it into JSON for the warmed session pipe, and waits for the receipt under the 15-second watchdog. The same TLS session observes PostgreSQL and commits the enqueue. One producer XID covers eight bulk calls and eight scalar calls. The source limits each spec array to 1 MiB, splitting the first 504 rows into eight calls of 63 followed by eight scalar writes. The native stock counters confirm 8+8 calls. The transfer also checks returned row counts and nonzero WAL by statement.

The product checks its set claims in a transaction around `mesh_jobs.claim_batch_set_v1` and starts work only after confirmed COMMIT. The runner dispatches in its trusted shared Mesh process with LISTEN and the original 250 ms fallback poll. Its app pool uses eight warmed strict TLS sessions and records 1,024 probes. The handler makes its first standalone application write to `mesh_jobs_parity_attempts`, sleeps 100 ms, then makes a separate write to `mesh_jobs_parity_effects`. The original public exit path settles each completed job with scalar `mesh_jobs.settle_state`. The replay checks 512 distinct terminal XIDs, 1,024 distinct application XIDs disjoint from terminal and producer XIDs, all job keys and payload digests, ordered commits, exact row counts, drained runner reports, and cap and affinity. ## Native gates

- SETUP exercises exact inline and FILE on both shapes through the full 512-job workload in diagnostic phase. Every arm must reconcile before TIMING. The local Linux proof loaded the actual adapter as UID 65534 from a nonlistable stage, verified both profile allocations and fixture bytes, and exercised the repaired reconciliation closure. It did not execute the retained Linux ELFs or start PostgreSQL. SETUP supplies that physical proof.
- The pilot runs five Mesh arms twice in reversed order with a warmup and measured arm for each. The two 1×64 inline duplicates bound spread. The other arms are 1×64 FILE, 2×32 inline and the preselected 2×32 FILE. Retain each FILE and topology contrast on enqueue, submit, drain, last effect and late refill.
- Both rotations must pass. FILE must save more than 20 ms and the duplicate spread on enqueue in both shapes, with drain regression bounded by the greater of 20 ms and the duplicate spread. Splitting must improve drain and move the last committed effect earlier by more than 25 ms and the duplicate spread, with each transport. Split FILE must save more than 100 ms and the duplicate spread from submit relative to the faster duplicate, and more than 10 ms and that spread relative to both single changes. The scorer requires every warmup and measured arm to pass the work, cap, identity and durability checks.
- Runner lifetime CPU must stay within 25% of the higher duplicate. Bracketed pinned host CPU must stay within 20%, and runner RSS within twice the higher duplicate. The expected peak is at most 13 TLS clients for 1×64 or 17 for 2×32. The scorer also retains disk, I/O wait and steal evidence and the SQL statement execution counters. Host CPU is a bracket across the pinned CPUs. SQL execution time and process CPU are separate measurements.

The split FILE candidate has a fresh 1×64 stock public Mesh bridge and the frozen 1×64 River, Oban and Apalis inventories. The result is a deployment comparison against stock peers.
