# Serialize the suffix after the first JSON escape

The released LARGE producer saves 12.55–14.28 CPU-ms against the move-only control on a submission of 64 plain frames. A single late escape in each dominant argument reverses the result in all six orders, costing 56.93–59.76 CPU-ms against that same control. These measurements cover admission preparation. The durable FILE trial uses the released producer.

For a stream consisting of the two measured kinds of submission, a linear mixture breaks even against move-only at 80.56–82.33% plain submissions across the six orders. For each order, divide its late-escape loss by the sum of that loss and its plain gain. This calculation uses paired CPU deltas from `report.profiles` in the [screen replay](../2026-11-25-public-large-canonical-string-linux/evidence/screen-91548db6e0ce/replay.json) at commit `299b138e3`. The production mix is unknown.

[candidate.patch](candidate.patch) is a full source overlay against `b3557273d72be3802bf189b284e7caaf5f3caa0f`. After validation, a qualifying dominant string takes the argument ownership transfer for both frame types. The encoder scans 128-byte blocks. On the first quote, backslash or control byte, it copies the plain prefix and passes the suffix to serde_json. That byte is ASCII, so the split preserves UTF-8. The suffix formatter omits the opening quote already emitted by the encoder. Serde supplies every escape and the closing quote. A fully plain string takes one scan and one copy.

Native qualification must compare exact canonical bytes, fingerprints, ABI errors and admission receipts with stock. Cover control characters, quotes and backslashes at the first and last byte and on both sides of a block boundary, multibyte UTF-8 crossing a boundary, multiple escapes and the rounded half-frame and 64 KiB thresholds. Retain the original invalid UTF-8, SQL, rollback and COMMIT fault cases. A later component comparison needs the released plain candidate and move-only control as well as duplicate stock, since each exposes a different possible regression.

The patch SHA-256 is `d222534fa93d172d8bd9429c882c9c51d4baa4d2742c3796ac654e2195af5105`. Applied to the pinned base, the resulting `compiler/mesh-rt/src/jobs/store.rs` hashes to `a353c1619923d84943c9d00d5bb8e441a109581b96cb7007c47e92da116f8164`. Verification so far covers source application and archive arithmetic. Compilation, correctness and performance are pending.
